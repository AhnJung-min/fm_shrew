# 화면 디자인 방침

이 문서는 FM 보좌관의 모양을 정하는 기준이다. 새 화면이나 고치는 화면은 이 문서의 토큰과 규칙을 따른다.
토큰의 실제 값은 `src/renderer/src/styles/app.css`의 `:root`가 기준이고, 이 문서와 다르면 CSS가 맞다.

## 1. 누가, 무엇을 위해 쓰는가

- 쓰는 사람: FM26을 하는 한국 사용자. 처음 쓰는 사람이 많다.
- 쓰는 때: 게임 옆 두 번째 모니터나 좁은 창(보통 1300×800, 좁게는 960 안팎)에서 게임과 번갈아 본다.
- 하는 일: 숫자를 읽고 비교하고, 가끔 고친다. 그래서 장식보다 **큰 글자, 높은 대비, 줄 맞춘 숫자**가 먼저다.
- 불만이었던 것: "가시성이 너무 안 좋다". 그래서 글자는 12.5px 아래로 내리지 않고, 본문 15px, 숫자는 크고 굵게 쓴다.

## 2. 방향: 조명이 켜진 밤 경기장과 전광판

바탕은 밤 경기장 하늘의 어두운 남색, 선과 글자는 조명 아래 흰색, 숫자는 전광판처럼 크고 굵게. 설정의 "화면 색"에서 블랙(무채색 검정)으로 바꿀 수 있다.

2026-11-27 사용자가 초록빛 바탕을 마음에 들어 하지 않아 "어두운 블루 계열이나 블랙"으로 바꿨다. 기본은 어두운 블루, 블랙은 같은 토큰 이름에 면과 글자 값만 바꾼 것이다(`app.css`의 `:root[data-theme='black']`). 뜻이 있는 색(초록·노랑·주황·빨강), 크기, 간격은 두 색 모두 같다.

처음 잡았던 안은 "거의 검은 바탕에 노란 포인트 한 가지"였다. 이것은 무엇에나 붙는 기본값이라 검토에서 바꿨다.

바꾼 것과 이유:

1. 바탕은 **어두운 남색**(처음에는 잔디색 초록이었으나 사용자 요청으로 바꿨다). 경기장 그림도 같은 계열의 작전판 색이다.
2. 화면의 뼈대(선택된 메뉴, 주 버튼, 링크, 선택된 줄)는 **흰색**으로만 표시한다. 노랑을 화면 포인트로 쓰지 않는다.
3. **색은 뜻이 있을 때만 쓴다.** 초록=좋음, 노랑=주목(최고 구간, 고친 값), 주황=주의, 빨강=위험. 같은 색을 장식에 쓰지 않으니 색이 보이면 읽을 거리가 있다는 뜻이다.
4. 포커스 링은 데이터에 쓰지 않는 **하늘색**이라, 흰 버튼 위에서도 어떤 색 위에서도 보인다.
5. 모든 카드를 같은 둥근 상자로 찍지 않는다. 위계를 세 층으로 나눈다(아래 4번).
6. 한 군데만 크게: **전광판 숫자**. 현재·잠재 능력, 점수, 인원 같은 핵심 숫자는 같은 서체로 크고 굵게, 자릿수를 맞춰(tabular) 쓴다.

## 3. 토큰

### 색

값은 어두운 블루 / 블랙 순서.

| 이름 | 값 | 쓰임 |
|---|---|---|
| `--bg` 밤하늘 | `#0a1324` / `#08090b` | 화면 바탕, 입력 칸 안 |
| `--surface` 관중석 | `#0f1b31` / `#101216` | 패널, 사이드바 |
| `--raised` 벤치 | `#16243f` / `#181b20` | 패널 안의 작은 덩어리, 버튼 |
| `--hover` | `#1e2e4d` / `#21252c` | 마우스를 올린 줄 |
| `--line` / `--line-strong` | `#263756` / `#5b7099`, `#2a2f37` / `#656e7c` | 구분선 / 입력·단추 테두리(어느 면과도 3:1 이상) |
| `--text` | `#eef3fb` / `#f2f4f7` | 본문, 제목 |
| `--text-2` | `#c6d1e4` / `#c9cdd5` | 보조 글자 |
| `--text-3` | `#95a5c2` / `#9aa1ad` | 흐린 글자(가장 밝은 면 위에서도 5.4:1 이상) |
| `--accent` 흰색(뼈대) | `--text`와 같음 | 선택·주 버튼·링크. 잉크는 `--accent-ink`(= `--bg`) |
| `--turf` / `--turf-stripe` / `--turf-line` | `#0e2140` / `#11264a` / `#3d5888`, `#12161c` / `#151a21` / `#465060` | 전술판·포지션 그림 |
| `--gold` | `#f7d65a` | 주목: 최고 구간 능력치, 고친 값, 추천 점수 |
| `--good` / `--warn` / `--bad` | `#5fdca0` / `#f5a64c` / `#f58a7c` | 좋음 / 주의 / 위험 |
| `--focus` | `#7cc7ff` | 키보드 포커스 링 전용 |

능력치 네 단계(게임과 같은 뜻, 색에 굵기와 윤곽이 함께 바뀐다):

| 단계 | 값 | 칩 |
|---|---|---|
| `a1` | 1~5 | 빨강 바탕, 보통 굵기 |
| `a2` | 6~10 | 회색 바탕, 보통 굵기 |
| `a3` | 11~15 | 초록 바탕, 굵게 |
| `a4` | 16~20 | 노랑 바탕, 아주 굵게 |

모든 글자 색은 어느 바탕 위에서도 4.5:1 이상이다(칩 안 글자 포함, 계산한 값은 `app.css` 머리말에 있다).
**색만으로 뜻을 전하지 않는다**: 톤은 글자(좋음·주의·위험)와 아이콘을, 능력치는 숫자와 굵기를, 고친 값은 테두리와 "원래 값" 글자를, 영입 추천 등급은 막대 색과 등급 글자(강력 추천·추천·고려·보류)를 함께 쓴다.

**"FM이 꺼져 있음"은 평소 상태다.** 사이드바, 시작 화면, 대시보드 구단 카드, 선수 서랍의 출처 안내, 에디터 안내, 영입 후보의 몸값 안내는 중립 점(`.dot.idle`, `--text-3`)과 `--text-2` 글자로 쓴다(`.note-idle`). 주황·빨강은 옛 플러그인, 쓰기 실패, 오류 같은 진짜 문제에만 쓴다. 영입 후보의 "고려" 등급도 경고처럼 보이지 않게 `--text-3`이고, 최고 등급(강력 추천)만 `--gold`이다.

### 글자

서체는 Pretendard 하나(앱에 들어 있는 가변 글꼴). 역할을 굵기와 크기로 나눈다.

| 역할 | 토큰 | 크기 / 굵기 |
|---|---|---|
| 전광판 숫자 큰 것 | `--fs-score-xl` | 56px / 800, 자간 -0.03em |
| 전광판 숫자 | `--fs-score` | 34px / 800 |
| 화면 제목(h1) | `--fs-h1` | 26px / 800 |
| 구역 제목(h2) | `--fs-h2` | 19px / 700 |
| 소제목(h3) | `--fs-h3` | 16px / 700 |
| 본문 | `--fs-body` | 15px / 400, 줄 높이 1.55 |
| 작은 글자 | `--fs-small` | 13.5px |
| 가장 작은 글자 | `--fs-micro` | 12.5px(이보다 작게 쓰지 않는다. 전술판, 칩, 범례, 레이더 눈금, 포지션 그림의 SVG 글자도 같다) |

한 줄은 한글 기준 40자 안팎(최대 `max-width: 68ch`)에서 끊는다. 라벨은 문장 그대로 쓰고, 영문 대문자 라벨·자간을 벌린 윗 라벨·가운뎃점(·)으로 이은 메타 문자열은 쓰지 않는다(메타는 `MetaLine`으로 간격을 두어 나눠 보여 준다). 화면 밖에서 만드는 글(`shared/insights.ts`, `club.ts`, `gameUi.ts`)은 쉼표나 문장으로 잇는다. 단어를 잇는 가운뎃점(재정·시설, 나이·국적)과 두 숫자 사이의 화살표(현재 126 → 잠재 144)는 괜찮다.

**전문 용어는 풀어 쓴다.** 화면에 바로 보이는 글에는 "표준편차"나 σ를 쓰지 않고 "상위권 평균보다 7점 높음", "기대 주급의 1.85배"처럼 쓴다. σ 숫자는 "어떻게 계산했나" 같은 접이식 안에만 둔다.

### 모양과 간격

- 둥글기: `--radius-xs` 4px(칩·태그), `--radius-s` 6px(단추·입력), `--radius-m` 10px(패널 안 덩어리), `--radius-l` 14px(첫 화면의 큰 덩어리). 한 화면에서 위계가 다르면 둥글기도 다르게.
- 간격은 4 단위: `--sp-1` 4, `--sp-2` 8, `--sp-3` 12, `--sp-4` 16, `--sp-5` 24, `--sp-6` 32.
- 그림자는 서랍처럼 화면 위에 뜨는 것에만 쓴다. 패널에는 쓰지 않는다.
- 움직임은 사용자가 한 동작에 반응할 때만(0.12초 안팎), `prefers-reduced-motion`이면 모두 끈다. 켤 때 자동으로 움직이는 것은 두지 않는다.

## 4. 레이아웃 원칙

위계는 세 층이다.

1. **첫 덩어리(hero)**: 화면에서 가장 먼저 읽을 것 하나. 다른 패널보다 밝은 바탕(`--raised`)과 큰 둥글기(`--radius-l`).
2. **구역 패널**: 바탕 `--surface`, 테두리 1px `--line`, 그림자 없음.
3. **덩어리(tile)**: 패널 안의 숫자·줄. 바탕 `--raised`, 둥글기 `--radius-m`.

```
┌────────┬──────────────────────────────────────────────┐
│ 로고   │ 화면 제목 (h1) 한 줄 설명                  [주 행동] │
│ 구단   ├──────────────────────────────────────────────┤
│ 메뉴   │ ┌ hero ─────────────────────────────────────┐ │
│ (설명  │ │ 오늘의 브리핑: 톤 배지 + 한 문장씩          │ │
│ 한 줄) │ └───────────────────────────────────────────┘ │
│        │ ┌ 패널 ───────────┐ ┌ 패널 ───────────┐      │
│ 상태   │ │ 제목 · 설명      │ │ 제목 · 설명      │      │
│        │ │  [58] [3] [2]   │ │ 막대 · 목록      │      │
└────────┴─┴─────────────────┴─┴─────────────────┴──────┘
```

- 정렬은 왼쪽. 숫자 열만 오른쪽 맞춤. 가운데 정렬은 빈 화면의 안내에만 쓴다.
- 구역은 두 칸(넓이 약 440px 이상일 때), 좁으면 한 칸. 표와 긴 목록은 전체 폭.
- 사이드바는 236px, 900px 이하에서는 아이콘만 56px.
- 제목 옆에는 한 줄 설명을 붙이고(설정, 선수 비교 포함), 처음 쓰는 사람이 막히지 않게 모든 빈 화면에는 다음 할 일을 단추로 둔다. 선수 비교의 빈 화면에는 선수 고르기와 주 단추("스쿼드로 가기")를 함께 둔다.
- 긴 안내는 한 문장만 보이고 나머지는 "자세히"(`details`) 안에 둔다. 표가 주인공인 화면(영입 후보)은 위쪽 도구를 두 줄 안쪽으로 줄여, 1304×800에서 표가 12줄 이상, 960×700에서 6줄 이상 보이게 한다. 그래도 창이 낮으면 표를 쥐어짜지 않고 도구와 표를 한 덩어리로 스크롤한다(`.targets-scroll`).
- 대시보드는 브리핑 바로 아래에 할 일(영입 추천, 계약 만료)을 두고, 칸은 제 높이만큼만 차지한다(`align-items: start`). FM이 꺼져 있으면 구단 재정·건강 카드는 한 줄 안내로 접는다.
- 선수 서랍은 1180px 이상에서는 표 옆에 붙고, 그보다 좁으면 오른쪽에 얹는다(전술판 옆 패널과 같은 기준).
- 백업 같이 패널이 위아래로 쌓이는 화면은 패널 사이에 `--sp-4` 간격을 둔다.
- 단계가 실제로 있는 곳(시작 화면의 세 단계)만 번호를 쓴다. 단계는 패스 길처럼 점선으로 이어 보여 주고, 끝난 단계는 색과 함께 체크 아이콘을 쓴다.

## 5. 부품 규칙

- **단추**: 높이 36px. 주 단추(`.btn.primary`)는 분필 바탕에 어두운 글자. 한 화면에 주 단추는 하나. 보조는 테두리, 약한 것은 `.ghost`(바탕만 비우고 `--line` 테두리는 남겨 단추로 보인다). 되돌릴 수 없는 것(키 지우기, 사본 지우기)은 `.danger`(평소에도 `--bad` 글자, 누르기 전 확인창은 그대로). 누르는 순간(`:active`)은 한 칸 눌리고 바탕이 어두워진다.
- **칩/세그먼트**: 켜진 것은 분필 테두리와 옅은 분필 바탕, 글자는 굵게.
- **태그**: 12.5px, 둥글기 4px. 내 팀·적용됨은 흰색, 고침은 노랑(`.tag.edited`).
- **금액**: 원화로, 게임과 같은 꼴로 쓴다(1,130억 원, 46.1억 원, 4.5억 원, 960만 원). 세이브와 계산은 게임의 기준 통화인 파운드이고, 보여 줄 때만 1파운드 = 1,920원(`WON_PER_POUND`, `shared/playerView.ts`)을 곱한다. 게임이 켜져 있으면 게임이 적어 준 원화 글자를 그대로 쓴다. 금액 뒤 조사는 `withJosa`로 붙인다("원"은 받침이 있어 "은").
- **입력**: 36px, 테두리 `--line-strong`. 포커스는 하늘색 링 2px.
- **표**: 머리글은 `--surface` 위에 붙고, 정렬된 열은 분필 글자와 굵게. 줄무늬는 아주 옅게. 선택된 줄은 분필 옅은 바탕과 왼쪽 막대 3px.
- **상태 배지**(좋음·주의·위험·참고): 아이콘 + 글자 + 옅은 색 바탕. 색 줄(border-left)로만 톤을 알리지 않는다.
- **고친 값**: 노랑 테두리 2px, 굵게, "원래 값 N". 에디터와 포지션 그림이 같은 규칙을 쓴다.
- **전술판**(스쿼드): 자리 하나가 상자 하나다(`.tp-slot`). 선수 이름·적합도 칩은 상자 안의 글자 줄이고, 역할 고르기는 밑줄만 있는 글자 칸, 보강 필요도는 "보강 필요도 25 보통" 글자 한 줄(누르면 그 자리 분석이 열린다)이다. 상자 안에 또 상자를 넣지 않는다.
- **스쿼드 진단 카드**: 알릴 것이 없는 카드(빈 목록)는 카드 틀 없이 한 줄(`.insight.quiet`)로 접는다. 살펴볼 카드는 색 줄 대신 전체 테두리를 주의색으로 칠한다.
- **선수 카드/서랍**: 얼굴, 이름, 한 줄 요약, 전광판 숫자(현재·잠재), 기본 정보, 능력치 세 줄, 포지션 그림 순서. 세 줄(기술·정신·신체)은 제목으로만 나누고 색으로 나누지 않는다(색은 능력치 단계를 위해 비워 둔다).
- **트레이 아이콘**(`src/main/trayIcon.ts`): `BrandMark`와 같은 도형을 남색 타일 위에 그린 32×32 PNG다. 의존성 없이 zlib만으로 도형을 그려 구웠다(정확한 도형과 색은 `BrandMark`가 기준이고, 바뀌면 다시 구워야 한다).
- **로고**(`Sidebar.tsx`의 `BrandMark`): 전술판의 한 수. 선수(O)에서 출발한 노란 패스 화살표가 공격수(X)에게 닿는다. 분필 선과 둥근 타일(`--raised`) 위에 화살표만 노랑이다. 구단이나 FM의 상표를 쓰지 않는다.
  - 고르는 과정: 한글 "보"를 짜 맞춘 글자 표식은 이름 옆에서 "보"가 두 번 보여 버렸다. 페널티 에어리어 조각은 쇼핑백으로 읽혀 버렸다. 센터서클과 하프라인은 예전 표식과 같았다. 그래서 O에서 X로 가는 패스를 골랐다.
  - 시험: 128px와 64px에서 O → X가 또렷하다. 32px와 24px에서 뜻이 읽힌다. 16px에서는 X가 흐려져 쓰지 않는다(최소 24px). 한 색(검정·분필 한 색)으로 바꿔도 O, X, 화살표의 모양으로 읽힌다. 어두운 바탕과 밝은 바탕 모두에서 확인했다.
  - 앱 아이콘 파이프라인이 저장소에 없어 앱 안의 SVG만 만들었다.

## 6. 덜어 낸 것(장식 점검)

검토에서 뺀 장식. 다시 넣지 않는다.

- 선수 카드 세 줄(기술·정신·신체) 위의 색 줄: 능력치 단계 색과 헷갈려서 뺐다.
- 브리핑 줄과 경기·알림 상자 왼쪽의 굵은 색 줄(border-left): 색 줄 대신 아이콘과 글자가 든 배지, 옅은 색 바탕과 얇은 테두리를 쓴다.
- 에디터 얼굴 둘레의 그라디언트, 가운뎃점으로 이은 메타 문자열.
- 카드는 두 층까지만 쓴다(패널 > 덩어리). 덩어리 안에 또 상자를 넣지 않는다.

## 7. 접근성 점검표

- 글자 대비 4.5:1 이상(실제 계산한 값은 CSS 머리말 주석에 적어 둔다).
- 입력·단추 테두리와 바탕 3:1 이상.
- 모든 단추·입력·접이식은 키보드로 닿고, 포커스 링이 보인다(`--focus` 2px, 간격 2px).
- 누를 곳의 크기는 가로세로 최소 32px(좁은 줄 목록은 줄 전체가 눌린다).
- 색만으로 뜻을 전하지 않는다.
- `prefers-reduced-motion`이면 전환을 끈다.
- 단어는 글자 중간에서 끊기지 않게 `word-break: keep-all`.

## 8. 뒤에 오는 화면(스쿼드, 영입 후보)에 대한 메모

- `--accent`가 노랑에서 분필로 바뀌었다. 노랑이 필요한 곳(최고 구간, 고친 값)은 `--gold`를 쓴다.
- `.ptable`, `.chip`, `.btn`, `.tag`는 새 토큰을 이미 따른다. 새로 만드는 부품은 위 3층 위계와 둥글기 규칙을 따른다.
- 경기장 그림(`--turf`, `--turf-line`)과 선수 얼굴, 구단 엠블럼 부품을 그대로 쓴다.
